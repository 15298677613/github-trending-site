一、本周结论

  • 85 条上榜记录，44 个去重项目；其中 21 个项目重复上榜，23 个仅出现 1 次。
  • 本周最清晰的主线不是“又一个聊天机器人”，而是给编码 Agent 增加可复用能力：工程技能、长期记忆、代码图谱、受控执行环境和长任务状态管理。
  • 持续性最强的是 TencentDB-Agent-Memory、pdf-inspector、DeepSeek-Reasonix，均上榜 5 天；AI 客户端增强方向中，addyosmani/agent-skills、obra/superpowers、mattpocock/skills 的热度和落地性最突出。
  • 最值得优先试装的组合是：工程 Skills + 代码图谱 MCP + 长期记忆。这三层分别约束工作方法、补充仓库上下文、沉淀跨会话知识，能力互补且不必更换现有客户端。
  • cloudflare/computer、loopx 代表下一阶段：Agent 不只“会写代码”，还需要可审计的执行环境、持久状态、预算和交接机制。

二、统计口径与数据限制

  1. “上榜次数”按项目在六份日报榜单表中出现的天数计算，同一天只计一次。
  2. “总 Star 变化”使用该项目首次与最后一次上榜时的 API 总 Star 快照之差。
  3. “今日新增”是 Trending 在采集时刻给出的滚动热度指标，不能跨天直接求和；部分日报采集时刻不同，因此它与 API 总 Star 变化不会严格相等。

七、推荐落地顺序

方案 A：个人开发者，半天内见效

  1. 在 mattpocock/skills 与 addyosmani/agent-skills 中各选一个窄技能，不要一次安装全部。
  2. 用同一个真实任务比较安装前后：需求遗漏、测试覆盖、返工次数和 token 消耗。
  3. 保留有效技能并按自己的技术栈裁剪；没有稳定收益的立即移除。

方案 B：中大型仓库，一周试点

  1. 部署 code-review-graph，只给一个测试仓库建立图谱并以 MCP 接入客户端。
  2. 接入 TencentDB-Agent-Memory 的只读知识资产，禁止自动写入和跨项目共享。
  3. 对三到五个 PR 记录评审引用准确率、token、延迟和漏报；达标后再扩大范围。

方案 C：长任务与自动执行

  1. 用 loopx 保存目标、证据、预算和停止条件。
  2. 需要远程执行时，再把 cloudflare/computer 作为隔离执行环境接入。
  3. 在生产化之前补上 uber/ADR 或等价观测/检测层，默认最小权限，不向 Agent 暴露长期凭据。
