## 项目详情

### 1. [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design)

- **它是什么：** 面向 Claude Code、Codex 等编码代理的编辑型图表设计技能/插件，内置 29 类图表，输出自包含 HTML 与 SVG，强调清晰排版、品牌色和可继续编辑，而不是依赖 Mermaid 的默认视觉样式。
- **有什么作用：** 把“帮我画架构图、流程图或比较图”变成可复用的设计流程，让代理能按统一视觉规范选择图表类型、组织信息并交付可嵌入文档或网页的素材。
- **可以用于：** 技术架构、产品流程、路线图、系统关系、方案对比、研究摘要、汇报配图和品牌化知识内容。
- **如何快速上手：** Codex 中执行 `codex plugin marketplace add cathrynlavery/diagram-design`，再执行 `codex plugin add diagram-design@diagram-design`；重启会话后直接描述要表达的信息、目标读者、尺寸和品牌颜色。第三方插件应先阅读其 `SKILL.md` 与脚本权限，再用于敏感项目。

### 2. [macro-inc/macro](https://github.com/macro-inc/macro)

- **它是什么：** 一个面向团队的统一工作空间，把邮件、聊天、文档、任务、通话、CRM 和 Agent 通过 `@` 关联起来，并共享 AI 记忆。仓库是大型 Rust/TypeScript 单体仓，包含桌面/网页客户端、众多服务、基础设施定义与本地依赖栈。
- **有什么作用：** 减少信息散落在不同应用中的上下文切换，使人、文档、对话与任务能在同一语义空间里互相引用，方便 AI 在团队级上下文中工作。
- **可以用于：** 项目协作、客户跟进、知识沉淀、跨渠道检索、会议与邮件联动，以及构建带长期上下文的内部 AI 工作台。
- **如何快速上手：** 只想体验时优先使用官方产品；源码运行需先安装 Nix 和 Docker Compose，随后 `git clone https://github.com/macro-inc/macro.git`、`cd macro`、`nix develop`，最后执行 `just run_local --no-doppler`。本地栈会启动 Postgres、Redis、OpenSearch、Kafka、LocalStack 与 FusionAuth，资源占用较高，生产部署前应单独评估安全、密钥和运维成本。

- **它是什么：** 一个约 14 MB、面向手机、穿戴设备、智能家居和机器人等小型设备的端侧基础模型/工具调用运行库。它根据函数签名和描述选择工具、补全参数并执行调用循环。
- **有什么作用：** 在不持续依赖云端大模型的情况下，为边缘设备提供轻量的自然语言意图理解与函数调用能力，降低延迟、网络依赖和数据外传。

- **如何快速上手：** 执行 `pip install cactus-needle`；在 Python 中用 `@needle.tool` 装饰带类型签名和清晰 docstring 的函数，再以 `needle.Needle(tools=[...]).run("用户请求")` 运行。先用只读、低风险工具做准确率测试，再逐步开放会产生现实影响的动作。

- **它是什么：** 一款完全在本机 GPU 上运行的桌面应用，可用本地 AI 从单张或多张图片生成 3D 模型；前端/桌面层以 TypeScript 为主，后端使用 Python 模型栈。
- **有什么作用：** 降低图片到 3D 资产的制作门槛，同时让素材和生成过程保留在本机，适合隐私敏感或不想按云端次数付费的工作流。
- **可以用于：** 游戏与 AR/VR 原型、商品三维预览、概念设计、快速建模、3D 打印前期草模和本地生成式设计实验。
- **如何快速上手：** 在仓库根目录运行 `npm install`；进入 `api` 创建并激活 Python 虚拟环境，执行 `pip install -r requirements.txt`，回到根目录运行 `npm run dev`。开始前检查 README 的 GPU/驱动要求，并用低分辨率素材先验证显存与生成时间。

### 17. [altic-dev/FluidVoice](https://github.com/altic-dev/FluidVoice)

- **它是什么：** macOS 本地语音听写应用，支持设备端语音识别和自训练 AI 文本增强，也可选择 OpenAI、Groq 或兼容接口作为云端增强提供商。
- **有什么作用：** 用全局快捷键把语音直接输入任意应用，在尽量不上传音频的前提下提高写作、编码和沟通效率。
- **可以用于：** 日常听写、无障碍输入、会议后快速记录、邮件与文档起草、编程注释、长文本口述和多语言语音输入。
- **如何快速上手：** macOS 上执行 `brew install --cask fluidvoice`，或从最新 Release 下载；首次启动授予麦克风和辅助功能权限，设置全局快捷键并选择语音模型。若启用云端增强，应确认敏感内容处理政策；本地增强模型可减少数据外传。

## 观察与建议

1. **最强机会在“Agent 可控性”而非单纯聊天。** 图表技能、专业角色、上下文图、模型路由、RAG 和共享记忆都在解决同一个问题：让 Agent 的输入、工具、知识、身份和输出更稳定、更可治理。
2. **评估时先分清产品成熟度。** [macro-inc/macro](https://github.com/macro-inc/macro)、[holaboss-ai/holaOS](https://github.com/holaboss-ai/holaOS) 属于完整工作台；[cactus-compute/needle](https://github.com/cactus-compute/needle)、[NVIDIA-NeMo/Switchyard](https://github.com/NVIDIA-NeMo/Switchyard)、[semantica-agi/semantica](https://github.com/semantica-agi/semantica) 更像可嵌入基础组件。选型前应分别验证权限模型、稳定性、延迟、成本和数据边界。
3. **本地 AI 不等于低门槛。** [Lightricks/LTX-2](https://github.com/Lightricks/LTX-2) 的权重体积和显存要求很高；[lightningpixel/modly](https://github.com/lightningpixel/modly)、[unslothai/unsloth](https://github.com/unslothai/unsloth) 也依赖合适的 GPU/驱动。先用发行版、示例模型或云端演示完成小规模验证，再投入下载和部署。
4. **许可证需要逐层核对。** 仓库代码、子目录技能、模型权重、训练数据和生成内容可能采用不同条款；表中“API 未声明”不代表可任意商用。
