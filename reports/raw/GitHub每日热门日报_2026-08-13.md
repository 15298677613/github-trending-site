## 项目详情

### [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design)

**它是什么：** 一套面向 Claude Code、Codex 和 Pi 的图解设计 Skill。仓库描述标称覆盖 29 类编辑型图表，以自包含 HTML 与 SVG 生成架构图、流程图、时序图、状态机、ER 图、时间线、象限图、树图等，并提供亮色、暗色和完整编辑风格。

**有什么作用：** 把内容删减、视觉层级、品牌颜色、对比度和版式选择固化为可复用规则，让编码代理输出比通用 Mermaid 图更接近文章、报告和产品文档中的成品视觉；静态 HTML 默认无需构建，便于浏览器预览和后续编辑。

**可以用于：** 技术架构说明、产品流程、API 调用时序、组织与数据关系、研究报告图解、博客插图，以及把已有 draw.io 或 Mermaid 内容重新绘制为统一品牌风格。

**快速上手：** Codex 中运行 `npx skills add https://github.com/cathrynlavery/diagram-design --skill diagram-design`。安装后直接描述需求，例如“为前端、后端、数据库和 Redis 画一张架构图”；先在浏览器检查生成的 HTML/SVG，再按仓库说明导出 PNG 或 SVG。若要长期修改风格指南，建议克隆仓库后使用本地可编辑安装，避免更新覆盖自定义内容。

### [msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents)

**它是什么：** 一个跨工具的专业 Agent 角色库。每个角色包含性格、使命、工作步骤、交付物、质量指标和沟通方式，覆盖工程、设计、产品、测试、安全、营销、销售、运营、研究、财务和游戏开发等多个部门。

**有什么作用：** 把常见岗位的方法论和检查清单封装成可安装资产，减少团队反复编写角色提示词的成本，也让同一专业流程能在 Claude Code、Codex、Cursor、Gemini CLI、OpenCode 等工具间迁移。

**可以用于：** 给编码助手增加前端开发、代码审查、UI 设计和测试专家；组合产品经理、营销和销售角色完成小型“AI 代理团队”；也可作为 Agent 文件结构和提示工程的参考库。

**快速上手：** 最省事的是下载跨平台 Agency Agents 桌面应用；macOS 可运行 `brew install --cask msitarzewski/agency-agents/agency-agents`。命令行用户可克隆仓库后先执行安装脚本的 `--dry-run`，再按工具、部门或单个角色选择性安装；不要一次启用大量互相重叠的角色，先为任务明确唯一负责人和交付边界。

### [stablyai/orca](https://github.com/stablyai/orca)

**它是什么：** 一个面向并行编码代理的 Agent Development Environment（ADE），可统一运行 Codex、Claude Code、OpenCode、Pi 等代理，并利用独立 Git worktree 隔离任务；还提供终端分屏、嵌入式浏览器、设计模式、SSH worktree 和移动端伴侣。

**有什么作用：** 将“为多个代理建立隔离分支、分派同一或不同任务、监控进度、比较结果、审查差异并合并”的手工流程产品化，减少终端切换和上下文丢失。

**可以用于：** 同一需求的多方案竞赛、实现/测试/文档并行处理、远程 VPS 上运行代理、比较不同模型的代码结果、从移动端查看长任务通知，以及把 GitHub/Linear 工作项直接转成隔离工作区。

**快速上手：** 从项目下载页或 Releases 获取 Windows、macOS、Linux 安装包，打开已有 Git 仓库并配置本机已安装的编码代理，再为任务创建独立 worktree。首次使用先做一个小改动，验证 worktree、分支、Diff 和合并流程；不要让多个代理直接写同一工作目录，合并前运行项目测试并人工审查。

### [semantica-agi/semantica](https://github.com/semantica-agi/semantica)

**它是什么：** 面向 Context Graph、知识图谱、决策智能和可问责 AI 的图原生基础设施。它支持摄取文档和结构化数据、抽取实体关系、构建 RDF/LPG 图谱、混合检索、规则推理，并记录决策、因果链和来源信息。

**有什么作用：** 给 RAG 或 Agent 系统补充结构化关系、时间信息和 provenance，使团队能查询“为什么得到这个结论”“哪些事实影响了决策”，并为监管审查或内部治理保留机器可读证据。

**可以用于：** 金融、医疗、法律和政府等高要求场景的 AI 审计；企业知识图谱、实体消歧、决策影响分析、合规门禁；以及作为多 Agent 共享上下文、记忆和检索层。

**快速上手：** 执行 `pip install semantica`，在 Python 中从 `semantica.context` 导入 `ContextGraph`，先创建图并写入节点、关系或决策，再调用遍历、快照、决策链和导出接口验证。生产试用应先运行项目的环境检查，选择持久化图/向量后端，配置密钥和访问控制，并用真实审计样例验证来源链是否完整。

### [paperclipai/paperclip](https://github.com/paperclipai/paperclip)

**它是什么：** 一个开源、自托管的 AI Agent 团队管理平台。它以“公司”为组织模型，管理业务目标、组织结构、项目、预算、任务、审批、代理状态和成本，而具体执行仍由接入的 Agent 运行时完成。

**有什么作用：** 把多个 Agent 从零散会话提升为可治理的工作组织，提供目标对齐、职责分配、预算控制、活动追踪和人工审批，让团队能看见代理为什么工作、花费多少以及产出了什么。

**可以用于：** AI 原生创业团队实验、编码/研究/营销代理统一管理、自动化运营、预算受限的自治工作流，以及企业内部 Agent 控制台原型。

**快速上手：** 需 Node.js 20+；临时体验可运行 `npx --registry https://registry.npmjs.org paperclipai onboard --yes`。若使用官方安装脚本，先下载并核验 SHA-256，再人工检查脚本后执行。初次只接入低权限代理，明确预算、Secret 可见范围、外部写操作审批和紧急停机方式，再逐步开放真实业务资源。

### [NVIDIA-NeMo/Switchyard](https://github.com/NVIDIA-NeMo/Switchyard)

**它是什么：** NVIDIA NeMo 下的实验性多模型路由工具，包含启动器、独立 Rust 代理服务和可嵌入库。它可在 OpenAI Chat、Anthropic Messages 与 OpenAI Responses 协议之间转换，并支持随机路由、LLM 分类器路由、信号驱动的阶段路由和自定义算法。

**有什么作用：** 在编码代理和多个模型后端之间建立统一入口，让系统按请求类型或运行信号选择模型，同时用 Prometheus 指标观察请求量、错误、延迟、Token 和路由开销。

**可以用于：** 给 Codex、Claude Code 或 OpenClaw 接入多模型策略；构建统一 LLM 网关；研究质量、成本与延迟之间的动态路由；或把路由算法嵌入已有 Rust Agent 基础设施。

**快速上手：** 安装 `uv` 后运行 `uv tool install --python 3.10 "nemo-switchyard[cli]"`，设置 `OPENROUTER_API_KEY`，再以 `switchyard launch codex --model switchyard` 启动。若做独立服务，可执行 `cargo install --locked switchyard-server`，准备 `routes.toml` 后先用 `--dry-run` 校验。README 明确标注其为 pre-alpha、API 可能大幅变化且不适合生产，应只在隔离测试环境评估。

### [hugohe3/ppt-master](https://github.com/hugohe3/ppt-master)

**它是什么：** 一套让 Agent 从文档、主题或资料生成原生可编辑 PowerPoint 的工作流。它不仅排版文本，还能生成母版、原生形状、转场、动画、数据图表、表格、公式和讲者备注音频，并支持自有 PPTX 模板。

**有什么作用：** 把内容梳理、设计规范确认、图像获取、SVG 生成、质量检查和 PPTX 导出连成可复用流水线，产物可以继续在 PowerPoint 中编辑，而不是一组扁平截图。

**可以用于：** 研究报告、课程课件、咨询方案、产品发布、数据新闻、公司模板复用、带旁白演示文稿，以及把 PDF/DOCX/网页资料转成结构化幻灯片。

**快速上手：** 准备 Python 3.10+，执行 `git clone https://github.com/hugohe3/ppt-master.git`、进入目录并运行 `pip install -r requirements.txt`；也可用 `npx skills add hugohe3/ppt-master` 安装 Skill。把源文件放入 `projects/`，在该目录启动支持 Agent 的工具并输入“请基于 `projects/.../report.pdf` 生成 PPT”。先确认页面数、比例和设计规范，再检查预览与导出的 `exports/*.pptx`。

### [cactus-compute/needle](https://github.com/cactus-compute/needle)

**它是什么：** 一个开放的 4,500 万参数端侧工具调用和结构化抽取模型。权重被压缩进单个约 14 MB 的二比特引擎，完整会话约占 28 MB RAM；它用工具 Schema 编译出的字节级语法约束输出，并提供置信度门控和大工具目录检索。

**有什么作用：** 在不把输入发送到云端的情况下，让手机、穿戴设备、智能家居和机器人从自然语言选择工具、填写参数、抽取结构化数据；低置信度结果可交给更强模型或人工处理。

**可以用于：** 离线语音/文本助手、移动端函数调用、IoT 控制、表单和票据抽取、隐私敏感的本地自动化，以及把大量工具先检索到小候选集再调用。

**快速上手：** 执行 `pip install cactus-needle`，用 `@needle.tool` 装饰 Python 函数，清楚写出参数类型和 docstring，再创建 `needle.Needle(tools=[...])` 并调用 `run()`。推理引擎首次会从 Hugging Face 下载并缓存；正式执行设备动作前设置置信度阈值、参数白名单和人工确认，尤其不要让模型直接控制不可逆操作。

### [macro-inc/macro](https://github.com/macro-inc/macro)

### [localsend/localsend](https://github.com/localsend/localsend)

**它是什么：** 一个开源、跨平台的局域网文件与文本传输应用，可视为无需云端的 AirDrop 替代品，支持 Windows、macOS、Linux、Android、iOS 和 Fire OS。

**有什么作用：** 让同一局域网中的设备自动发现并点对点传输数据，避免注册账号、上传第三方云盘或依赖同一厂商生态；适合临时、大文件和隐私敏感的本地交换。

**可以用于：** 手机与电脑互传照片、跨系统办公文件交换、会议现场资料分发、家庭设备迁移、离线局域网共享，以及替代聊天软件中转文件。

**快速上手：** 优先从系统应用商店或包管理器安装，因为应用本身不带自动更新；Windows 可用 Winget，macOS 可用 App Store/Homebrew，Linux 可用 Flathub，移动端可用官方商店或 F-Droid。让发送和接收设备连接同一可信网络，打开应用、选择设备和文件并在接收端确认；公共 Wi‑Fi 下应核对设备名与接收提示。

### [shiyu-coder/Kronos](https://github.com/shiyu-coder/Kronos)

**它是什么：** 一个专为金融市场 K 线序列预训练的 decoder-only 基础模型族。它先把 OHLCV 等连续、多维行情量化为分层离散 Token，再用自回归 Transformer 学习市场序列，并提供 mini、small、base 等不同规模模型。

**有什么作用：** 把金融时间序列转换为可由统一模型处理的“市场语言”，用于价格/收益预测、表示学习、回测研究和在自有数据上微调，减少为每种量化任务从零设计专用模型的成本。

**可以用于：** 股票、期货和数字资产的研究性预测、特征生成、模型基准、行情情景分析、时间序列预训练与教学实验；不能把演示结果直接当成交易信号。

**快速上手：** 准备 Python 3.10+，克隆仓库后执行 `pip install -r requirements.txt`，从 Hugging Face 加载匹配的 `KronosTokenizer` 和 `Kronos`，再用 `KronosPredictor` 输入按时间排序的 OHLCV DataFrame。small/base 的上下文上限为 512；务必使用严格的时间切分、交易成本、滑点和样本外回测，避免数据泄漏，并将输出限定为研究而非个性化投资建议。

### [NanmiCoder/MediaCrawler](https://github.com/NanmiCoder/MediaCrawler)

**它是什么：** 一个覆盖小红书、抖音、快手、B 站、微博、百度贴吧和知乎等平台的内容采集工具，可抓取搜索结果、指定帖子、评论和回复，并支持 CDP/Playwright 登录、命令行及 WebUI。

**有什么作用：** 为公开内容研究提供统一的多平台采集入口，减少逐个平台实现登录、分页和字段解析的重复工作，并可把结果保存到 CSV、JSON、数据库等后端。

## 观察与选择建议

- **今天最值得立即试用：** 需要把技术内容转成高质量图解，可优先试 [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design)；希望给编码助手增加成体系的岗位方法，可试 [msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents)。

- **面向私有数据与上下文：** 强调图关系、决策来源和审计时选择 [semantica-agi/semantica](https://github.com/semantica-agi/semantica)；需要完整文档 RAG 平台时选择 [infiniflow/ragflow](https://github.com/infiniflow/ragflow)；端侧工具调用和离线隐私场景可关注 [cactus-compute/needle](https://github.com/cactus-compute/needle)。
- **面向内容生产：** 可编辑演示文稿看 [hugohe3/ppt-master](https://github.com/hugohe3/ppt-master)，本地高规格音视频生成研究看 [Lightricks/LTX-2](https://github.com/Lightricks/LTX-2)，但后者的模型下载和硬件门槛明显更高。
