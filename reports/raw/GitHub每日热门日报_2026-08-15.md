## 项目详情

### 1. [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design)

- **它是什么：** 面向 Claude Code、Codex 等编码代理的编辑型图表设计技能/插件，内置 29 类图表，输出自包含 HTML 与 SVG，强调清晰排版、品牌色和可继续编辑。
- **有什么作用：** 把“画架构图、流程图或比较图”变成可复用的设计流程，让代理能按统一视觉规范选择图表类型、组织信息并交付网页或文档素材。
- **可以用于：** 技术架构、产品流程、路线图、系统关系、方案对比、研究摘要、汇报配图和品牌化知识内容。
- **如何快速上手：** Codex 中执行 `codex plugin marketplace add cathrynlavery/diagram-design`，再执行 `codex plugin add diagram-design@diagram-design`；重启会话后直接说明信息、读者、尺寸和品牌颜色。第三方插件启用前应先检查 `SKILL.md`、脚本和权限范围。

### 2. [semantica-agi/semantica](https://github.com/semantica-agi/semantica)

- **它是什么：** 面向上下文与可问责 AI 的图原生基础设施，提供上下文图、决策记录、因果链追踪、相似决策检索、数据摄取和谱系分析等能力。
- **有什么作用：** 把 Agent 的输入、依据、决定和结果组织成可查询结构，让团队不仅知道“发生了什么”，还能追溯“为什么发生、参考了什么”。
- **可以用于：** Agent 审计、合规决策记录、企业知识图谱、数据血缘、历史决策复用、Graph RAG 和需要解释性的自动化系统。
- **如何快速上手：** 执行 `pip install semantica`，创建 `ContextGraph`，用 `record_decision(...)` 写入决策，再通过 `trace_decision_chain(...)` 或 `find_similar_decisions(...)` 查询；连接外部数据源时把令牌放入环境变量或密钥管理器。

### 3. [github/spec-kit](https://github.com/github/spec-kit)

- **它是什么：** GitHub 推出的规格驱动开发工具包，把项目原则、需求规格、技术计划、任务拆分和实施流程组织成可由多种编码 Agent 执行的命令与模板。
- **有什么作用：** 在写代码之前固定“要解决什么、如何验收、采用什么方案”，减少需求漂移和 Agent 直接跳入实现导致的返工，并保留可审查的开发轨迹。
- **可以用于：** 新功能设计、遗留系统改造、团队工程规范、PRD 到代码的流程衔接、多 Agent 协作，以及受合规约束的实施计划。
- **如何快速上手：** 安装 `uv` 后执行 `uv tool install specify-cli`，再运行 `specify init my-project --integration codex`；进入项目后依次使用 `/speckit.constitution`、`/speckit.specify`、`/speckit.plan`、`/speckit.tasks` 和 `/speckit.implement`。对已有目录使用 `--force` 前先提交或备份并审查文件差异。

- **有什么作用：** 让 Agent 复用本机登录态、Cookie、扩展和书签，同时把并行任务隔离到不同空间，减少与用户争用标签页和重复登录。
- **可以用于：** 已登录网站的资料整理、重复表单、后台操作、跨站信息收集、测试流程和多个浏览器任务并行执行。
- **如何快速上手：** 当前仅支持 macOS；可下载 Apple Silicon/Intel 应用，或执行 `npx skills add citrolabs/ego-lite` 安装 `ego-browser` 技能，首次任务会引导安装应用。之后在 Agent CLI 输入 `/ego-browser` 加自然语言任务。迁移 Chrome 数据会让 Agent 接触真实登录态，务必限制任务范围并对发送、购买、删除等动作保留人工确认。

### 17. [cursor/plugins](https://github.com/cursor/plugins)

- **它是什么：** Cursor 官方插件规范与多插件市场仓库，根目录清单汇集持续学习、团队工程、深度审查、文档画布、编排，以及 Gmail、Google Drive、HubSpot 等第三方集成。
- **有什么作用：** 用统一 manifest 把 Skills、Rules、MCP 服务和说明组合成可安装单元，扩展 Cursor Agent 的专业知识、工作流和外部服务连接。
- **可以用于：** 代码审查、CI 与交付、团队规范、文档可视化、多 Agent 编排、开发工具集成，以及经授权的企业 SaaS 操作。
- **如何快速上手：** 在 Cursor Marketplace 中搜索并安装所需插件；开发者可克隆仓库，查看根目录 `.cursor-plugin/marketplace.json` 和各插件的 `.cursor-plugin/plugin.json` 了解结构。连接 Gmail、CRM 等外部系统前，逐项检查发布者、权限、MCP 地址、密钥处理与每个子插件的许可证。

## 观察与建议

1. **先把 Agent 的“上下文和流程”做稳。** [github/spec-kit](https://github.com/github/spec-kit)、[semantica-agi/semantica](https://github.com/semantica-agi/semantica)、[infiniflow/ragflow](https://github.com/infiniflow/ragflow) 分别从规格、决策图和检索上下文解决可控性问题，比单纯更换模型更接近生产痛点。
2. **插件和共享登录态带来明显权限风险。** [cursor/plugins](https://github.com/cursor/plugins)、[holaboss-ai/holaOS](https://github.com/holaboss-ai/holaOS)、[citrolabs/ego-lite](https://github.com/citrolabs/ego-lite) 能显著扩展 Agent 能力，但也扩大了数据与操作半径；应坚持最小权限、测试账号、敏感动作确认和可审计日志。
3. **本地 AI 仍要先做硬件与许可证核算。** [cactus-compute/needle](https://github.com/cactus-compute/needle) 面向极小端侧场景，而 [lightningpixel/modly](https://github.com/lightningpixel/modly)、[unslothai/unsloth](https://github.com/unslothai/unsloth) 依赖合适的 GPU、驱动和模型权重。先用最小样例确认效果，再投入下载和部署。
4. **成熟度差异比 Star 数更重要。** [OpenCut-app/OpenCut](https://github.com/OpenCut-app/OpenCut) 明确处于重写期；[deepseek-ai/awesome-deepseek-agent](https://github.com/deepseek-ai/awesome-deepseek-agent) 是指南集合而非运行时；[ToolJet/ToolJet](https://github.com/ToolJet/ToolJet) 和 [rustdesk/rustdesk](https://github.com/rustdesk/rustdesk) 则是成熟产品型项目。选型时应分别评估可用版本、部署边界、维护成本和商业条款。
