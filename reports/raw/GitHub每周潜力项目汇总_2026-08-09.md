## 一、本周结论

- **85 条上榜记录，44 个去重项目**；其中 21 个项目重复上榜，23 个仅出现 1 次。
- 本周最清晰的主线不是“又一个聊天机器人”，而是给编码 Agent 增加可复用能力：**工程技能、长期记忆、代码图谱、受控执行环境和长任务状态管理**。
- 持续性最强的是 `TencentDB-Agent-Memory`、`pdf-inspector`、`DeepSeek-Reasonix`，均上榜 5 天；AI 客户端增强方向中，`addyosmani/agent-skills`、`obra/superpowers`、`mattpocock/skills` 的热度和落地性最突出。
- 最值得优先试装的组合是：**工程 Skills + 代码图谱 MCP + 长期记忆**。这三层分别约束工作方法、补充仓库上下文、沉淀跨会话知识，能力互补且不必更换现有客户端。
- `cloudflare/computer`、`loopx` 代表下一阶段：Agent 不只“会写代码”，还需要可审计的执行环境、持久状态、预算和交接机制。

## 二、统计口径与数据限制

1. “上榜次数”按项目在六份日报榜单表中出现的天数计算，同一天只计一次。
2. “总 Star 变化”使用该项目首次与最后一次上榜时的 API 总 Star 快照之差。
3. “今日新增”是 Trending 在采集时刻给出的滚动热度指标，**不能跨天直接求和**；部分日报采集时刻不同，因此它与 API 总 Star 变化不会严格相等。
4. 本周缺少 8 月 3 日日报，结论代表已有六天样本，不等同于完整七天榜单。

## 四、S 级：优先试用

S 级标准：能直接接入主流编码 Agent，能力增益清晰，且本周热度具有持续性或项目形态足够成熟。

### 1. addyosmani/agent-skills · 4 天 · 持续升温

- **接入形态**：Skill 集合。克隆仓库后按 README 放入 Claude Code、Codex、Cursor 等客户端的技能目录，先按名称启用单个技能。
- **增强能力**：把 Idea → Spec → Code → Test → QA → Ship 的生产级质量关卡变成 Agent 可重复执行的流程，适合 Web 开发、PR 审查、测试和发布。
- **评级理由**：连续四天上榜且末日热度继续抬升；跨客户端、低接入成本、日常使用频率高。
- **建议**：先挑代码评审或测试类技能做同一任务的前后对照，再决定是否启用完整流程，避免与团队现有规则重复。

### 2. obra/superpowers · 4 天 · 高位稳定

- **接入形态**：跨客户端 Skill/工作流框架，按 README 选择 Claude Code、Codex、Cursor 或 Gemini CLI 的安装方式。
- **增强能力**：需求澄清、规划、测试驱动、分步实现和复盘，把软件开发方法论固化为 Agent 行为。
- **评级理由**：四天持续高热，适配面广；相比单点工具，它直接改变复杂任务的交付质量。
- **建议**：从计划和测试相关技能开始；检查其规则与仓库内 `AGENTS.md`、`CLAUDE.md` 或 Cursor Rules 的优先级关系。

### 3. mattpocock/skills · 3 天 · 高热略降

- **接入形态**：小型可组合 Skills。将需要的目录复制到客户端 `.agents/skills` 或对应技能目录，重启后按技能名调用。
- **增强能力**：复用真实工程实践中的窄而明确的任务方法，特别适合 TypeScript/Web 工程和技能编写参考。
- **评级理由**：三天均处于高热区；粒度小、可修改，试用和退出成本低。
- **建议**：按需安装，不要整包无差别启用；先审查每个 `SKILL.md` 的工具权限和适用条件。

### 4. tirth8205/code-review-graph · 2 天 · 稳定

- **接入形态**：MCP + CLI。安装 Python 依赖、为仓库初始化 Tree-sitter 代码图谱，再把 MCP Server 配进支持 MCP 的客户端。
- **增强能力**：为大型仓库提供持久、增量的代码关系上下文；减少无关文件读取和 token 消耗，提高 PR 评审与变更影响分析精度。
- **评级理由**：上榜次数不算最高，但能力与 AI 编码客户端高度贴合，且 MCP 是标准化接入面。
- **建议**：选一个中大型仓库，对同一 PR 比较接入前后的 token、引用文件数和漏报率；图谱数据仅保存在受控位置。

### 5. TencentCloud/TencentDB-Agent-Memory · 5 天 · 高位持续

- **接入形态**：服务 + SDK/API，已有 Agent 框架接入方式；Claude Code、Codex、Cursor、Cline 若无原生适配，需要通过插件、MCP 或自定义工具桥接。
- **增强能力**：跨会话长期记忆、团队知识共享、Skill/LLM-Wiki/Code-Graph 资产治理，减少每次重新解释项目背景的成本。
- **评级理由**：本周上榜最持久、总 Star 快照增量最高；记忆是多个客户端共同缺失的基础能力。
- **建议**：先做单项目、只读知识库试点，明确数据保留、租户隔离和删除策略后再开放自动写入。

## 七、推荐落地顺序

### 方案 A：个人开发者，半天内见效

1. 在 `mattpocock/skills` 与 `addyosmani/agent-skills` 中各选一个窄技能，不要一次安装全部。
2. 用同一个真实任务比较安装前后：需求遗漏、测试覆盖、返工次数和 token 消耗。
3. 保留有效技能并按自己的技术栈裁剪；没有稳定收益的立即移除。

### 方案 B：中大型仓库，一周试点

1. 部署 `code-review-graph`，只给一个测试仓库建立图谱并以 MCP 接入客户端。
2. 接入 `TencentDB-Agent-Memory` 的只读知识资产，禁止自动写入和跨项目共享。
3. 对三到五个 PR 记录评审引用准确率、token、延迟和漏报；达标后再扩大范围。

### 方案 C：长任务与自动执行

1. 用 `loopx` 保存目标、证据、预算和停止条件。
2. 需要远程执行时，再把 `cloudflare/computer` 作为隔离执行环境接入。
3. 在生产化之前补上 `uber/ADR` 或等价观测/检测层，默认最小权限，不向 Agent 暴露长期凭据。
